## 第 3 页 · 项目背景与痛点

**为什么做？**
- 中草药种类逾万、外观相似度高，传统辨认高度依赖经验；普通用户、基层人员很难快速准确识别。
- 药性、归经、配伍禁忌、方剂知识体量大且零散于古籍药典，查阅效率低。
- 市面识别工具大多"只识图、不识药"：识别完即结束，缺中医药知识联动。

**共性风险**
- 相似药材极易混淆，误识别 + 误用药 = 健康风险；现有工具缺少置信度提示与风险警示。
- 本系统定位为**科普辅助工具**：结果必须附带医疗风险提示，不能替代执业医师诊断。

**目标用户**
- 普通爱好者 / 中医药学生 / 基层从业者 / 科普工作者。

## 第 4 页 · 系统总览与总体架构

**四层架构**
- **输入层**：药材图片（原植物 / 饮片 / 干药材）+ 可选文本描述（性味 / 归经 / 功效 / 提问）。支持拖拽、点击、Ctrl+V 粘贴。
- **多模态引擎**：Swin-Tiny 视觉编码 + BERT 中文文本编码 + HCA 跨模态注意力融合，输出识别结果与统一表征。
- **知识服务层**：中医药知识图谱（200+ 药材、12 首经典方剂、内置十八反/十九畏）+ RAG 语义检索 + 方剂/相似药推荐。
- **交互层**：新中式 Web 单页应用 + Gradio 调试界面 + FastAPI REST API（可服务化）。

**核心链路**
识别 → 解析（药性/归经/功效/毒性）→ 推荐（相似药/配伍/方剂）→ 可解释（热力图/推理路径/来源标注）。

## 第 5 页 · 模块一：多模态识别引擎（技术核心）

**技术选型（为 8G 显存优化）**
- 视觉编码器：**Swin-Tiny**（window attention，约 2.6G 显存；备选 EfficientNet-B0 / ResNet50 / ConvNeXt-Tiny）。
- 文本编码器：**BERT-base-chinese**（冻结主干，仅训练投影层，省算力）。
- 融合模块：**HCA-Fusion 层级式跨模态注意力融合**（自研）。
- 分类头：多模态分支 + 纯视觉保底双分支。

**关键设计**
- 模拟中医"望闻问切"互补判断：视觉 token 与文本 token 互为 query/key/value 做交叉注意力，再自注意力精炼，池化为统一表征。
- 双分支保底：文本为空时自动走纯视觉分支，从根本上保证"无文本也能靠图识别"。
- 启用 ImageNet 预训练微调（关键经验）：从零训练仅 15–20% acc，微调后纯视觉达 90%+。

## 第 6 页 · 模块一（续）：识别流程与可解释

**推理流程**
1. 图片 → Swin-Tiny 提特征 → 投影到 embed_dim（512）。
2. 文本 → BERT 提 [CLS] → 投影到同维度。
3. HCA 融合 → 多模态 logits（有文本）/ 纯视觉 logits（无文本）。
4. 输出 Top-5 识别 + 置信度徽章。

**易混鉴别**
- 内置 **16 组**常见易混淆药材对（白术/苍术、半夏/天南星、人参/党参、枸杞/地骨皮…）。
- 输出外观差异 + 简易鉴别法（嗅闻 / 口尝 / 水试）+ 功效与毒性提示，辅助用户人工复核。

---

## 第 7 页 · 模块二：中医药知识图谱

**构建方式**
- 内存版 Networkx（可选 Neo4j 持久化），从 CSV 加载药材节点与多类型关系。
- 规模：**200+ 药材节点、12 首经典方剂、151 条增量字段（别名/病症/个体禁忌）**。

**关系类型（边）**
- `paired` 相须相使（常同用，双向）
- `incompatible` 十八反（绝对禁用同方）
- `restraint` 十九畏（尽量避免同方）
- `category` / `meridian` 功效分类与归经维度节点

**内置领域常识（安全红线）**
- 硬编码十八反（甘草×甘遂、藜芦×人参…）、十九畏（人参×五灵脂…）歌诀规则，即使数据表未收录的药材也能被查询、检索与可视化，避免盲区。
- 毒性识别：从性味文本自动提取"大毒/有毒/小毒/微毒"等级，强制弹窗警示。

## 第 8 页 · 模块三：特性检索与方剂推荐

**特性检索**
- 输入"味甘平，归肝肾经""清热明目"等自然语言。
- 解析为「性味 / 归经 / 功效」三类条件，逐味打分。
- 输出「完全匹配 / 部分匹配」卡片，印章式角标；同时支持按药材名批量查询。

**相似药推荐**
- 按功效分类重叠 × 3 + 功效文本 n-gram × 2 + 性味 × 1 + 归经 × 1 综合打分，仅推荐功效相近者，辅助辨证选药。

**方剂推荐**
- 基于"主治功效匹配 + 常用配伍 + 禁忌规避"打分排序：命中十八反/十九畏的药直接剔除，从源头规避危险配伍。
- 返回方剂组成、来源、主治、用法、警示，并标注配伍风险。

---

## 第 9 页 · 模块四：RAG 问答与可解释性

**RAG 增强问答**
- 本地 BERT 对知识图谱切片（药材条目 / 配伍 / 禁忌）做中文语义向量检索，为 LLM 组装"专家上下文"。
- 检索策略：药名精确命中优先 + 语义 Top-K 补充；回答末尾附「知识库来源」折叠卡片，减少幻觉。
- 离线可用、零新增依赖；BERT 加载失败自动降级为关键词匹配，不抛异常、功能不中断。
- 外部 LLM（智谱 GLM，OpenAI 兼容）未配置 Key 或调用失败时，自动降级返回本地知识图谱结果。

**可解释性**
- **Grad-CAM 热力图**：滑块实时调节叠加透明度，直观展示模型"看哪里"做判断。
- **推理路径**：识别 → 图谱查询 → 推荐 的全链路可追溯，回答附来源标注。

## 第 10 页 · 模块五：交互展示与平台接入

**新中式 Web 前端（推荐入口，纯 HTML/CSS/JS，FastAPI 托管）**
- 图片识别 / 特性检索 / Grad-CAM / AI 对话 / 药材关系图谱 五个页签。
- 关系图谱：力导向网络（拖拽/缩放/点击），聚焦单药查看配伍与禁忌；红色虚线=十八反、橙虚线=十九畏、绿实线=相须相使。

**Gradio 演示（调试/备用）**：与前端统一主题，5 页签一致。

**REST API 服务化（`python main.py --mode serve`）**
- `/predict` 识别、`/search` 检索、`/explain` 热图、`/chat` 对话、`/graph` 图谱 JSON、`/herbs` 药材列表。
- 端侧部署：导出纯视觉分支为 TorchScript（`tools/export_model.py`），输入 [B,3,224,224]，输出 [B,163] logits，无需 Python/文本模型。

## 第 12 页 · 官方评估指标

**评估设定**
- 数据集：val 集 **10000 张，163 类**；权重 best_model.pth（Epoch 5，510.9 MB）。
- 推理：有文本走多模态，无文本走纯视觉分支。

**核心指标**
- 多模态（有文本）：Accuracy **0.9995**，Top-5 **1.0000**
- 纯视觉（无文本）：Accuracy **0.9548**，Top-5 **0.9965**
- 文本辅助增益：Δacc = **+0.0447**

**错误分析（诚实呈现）**
- 163 类中 **159 类 precision/recall/f1 全部 = 1.00**；错误仅 4 类，且全部集中在"同药不同形态"（首乌藤块/片、天麻块/片）互混——属人为拆类的固有难度，非识别缺陷。
- 最难的首乌藤块/片模型仍能 95% 区分。

## 第 13 页 · 技术栈与部署

**技术栈**
- 视觉：timm（Swin-Tiny 等）｜ 文本：HuggingFace Transformers（BERT）｜ 融合/分类：PyTorch
- 图谱：Networkx，CSV 数据驱动｜ 检索：本地 BERT 语义向量（CPU）
- 服务：FastAPI + Gradio｜ 前端：原生 HTML/CSS/JS

**部署与硬件**
- 训练/推理面向 **8G 显存**（batch_size=16，image_size=224；OOM 时降至 8 / 192）。
- 一键环境：`setup_env.bat` / `setup_env.sh`；环境检查 `check_environment.py`。
- 服务默认绑定 0.0.0.0，同局域网设备可直接访问；公网可借内网穿透或云服务器。
- 端侧：TorchScript 导出纯视觉分支，适合快速识图。

## 第 14 页 · 创新点

1. **多模态互补识别**：视觉 + 文本 + HCA 跨模态注意力融合，文本辅助增益 +4.47 个点，模拟中医"望闻问切"互补判断。
2. **双分支保底架构**：纯视觉分支保证无文本也能识别，工程上彻底消除"缺文本即失效"的单点风险。
3. **知识图谱驱动的解析与推荐**：把识别结果自动联动药性/归经/功效/毒性，并基于十八反/十九畏做禁忌规避，输出"识别—解析—推荐"闭环。
4. **RAG 可溯源问答**：本地语义检索 + 来源标注，离线可用、自动降级，显著降低大模型幻觉。
5. **可解释与安全并重**：Grad-CAM 热力图 + 推理路径 + 毒性强制警示 + 置信度提示，把"可解释"和"安全红线"做成默认能力。
6. **轻量可落地**：8G 显存友好、纯前端零构建、REST API 服务化、端侧可导出，兼顾演示与工程交付。

## 第 15 页 · 不足与改进方向（诚实自检）

**当前不足**
1. **数据规模与覆盖有限**：识别目标 163 类、图谱 200+ 药材，距真实中草药万级品类差距大；长尾/稀有药材样本少，依赖小样本（Prototypical Network）补足，泛化待验证。
2. **块/片形态易混**：同药不同形态（首乌藤、天麻）仍会互混，需要更细粒度形态标注或形态归一化预处理。
3. **知识图谱偏静态**：内存版 Networkx 规模受限，未启用 Neo4j 持久化；方剂仅 12 首，知识深度与时效性不足。
4. **文本依赖人工标注**：药性/描述文本需结构化录入，未做从古籍/药典的自动抽取；RAG 语料覆盖有限。
5. **LLM 能力受限于外部 Key**：深度问答依赖智谱 GLM，无 Key 时退化为本地检索，解释性下降。
6. **缺少量化与对抗评测**：未系统做对抗样本、光照/角度鲁棒性、跨域（手机拍/网图）泛化测试。
7. **安全边界有限**：仅做科普提示，无在线药师审核、无用药剂量/禁忌的个性化风险评估。

**改进方向**
- 扩充样本与细粒度标注（含形态变体）；接入 Neo4j 与更大方剂/古籍语料。
- 引入自动知识抽取（LLM/规则）丰富图谱；增加鲁棒性与对抗评测。
- 构建"识别 + 风险分级 + 人工复核"闭环，明确科普与诊断边界。

## 第 17 页 · 总结与交付物

**总结**
- 一套"识别—解析—推荐—可解释"闭环的中草药多模态智能体，在 8G 显存下达到多模态 0.9995 / 纯视觉 0.9548 的官方指标。
